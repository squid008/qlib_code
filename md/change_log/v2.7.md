## [2.7.0] - 2026-10-15

### 含入场价的离场公式：**不再限制字段**——改成「预计算列 + 骨架」✓（用户 2026-10-15 指正 ✓）

**用户原话**：「回测面板只取到 C/O 啥意思？离场信号只支持 C 和 O？那不对，高开低收量啥的都得支持啊，
还有换手率啥的都要能作为离场信号呀，还有比如市值小于一亿之类的」。

**先纠正一个范围**：**不含入场价的**离场公式**本来就没有任何限制** ✓ —— 它们走普通面板路径
（整列预计算 ✓），`H/L/C/O/V`、换手率、市值、`MA/EMA/递推组`… **全都能用** ✓
（这条 v2.5.0 起就成立 ✓，`Lt($market_cap,100000000)` 现在就能当离场信号 ✓）。

**认账的是"含入场价"那一支** ✗：v2.6.0 的实现把它做成"逐日只喂当日 C/O 行"⇒ 天然只支持 C/O ✗。
⇒ v2.7.0 改成 **"能预计算的全预计算、剩下的小骨架逐日算"**：

```
CLOSE < ENTRY_PRICE*0.95 AND TURNOVERRATE > 2 AND MA(CLOSE,5) < MA(CLOSE,20)
        └────────────── 骨架（逐日代入入场价 ✓）──────────────┘
                          └── 与入场价无关的子树 ⇒ 序列化成普通表达式 ⇒ **当附加字段列交给面板算** ✓
```
- **与入场价无关的子树**（`MA(CLOSE,5)` / `TURNOVERRATE` / `MARKET_CAP` / `$high` / 递推组…）
  ⇒ 由 `single_test` 的既有取数链当普通列算出来 ✓ ⇒ **任意字段、任意算子都能与入场价混用** ✓；
- 剩下的**骨架**（四则 / 比较 / `And/Or/Not` / `If` / `Between` + 两个入场价叶子）⇒ 回测里
  **逐日代入当天入场价向量**求值 ✓（等价于 v2.6.0 的机制 ✓，但行情部分全部换成预计算列 ✓）；
- 预计算列**只在真的用了入场价时才多算** ✓（不用 ⇒ 一列都不加 ⇒ 零额外成本 ✓）；
- 骨架里唯一不支持的仍是"**对入场价本身**取历史"✗（`REF(ENTRY_PRICE,1)` / `MA(ENTRY_PRICE,5)`）——
  语义也不清（期间可能已换仓 ✓）⇒ **编译期报错**并给出可写写法 ✓；
- 实现要点：`Node.raw` **只有算子名** ✗（不是子树原文）⇒ 新增 `_ast_to_expr` 把子树**序列化回
  qlib 表达式** ✓；骨架求值**复用递推内核那张逐元素算子表**（`recursion._OPS` ✓）⇒ NaN 比较恒假、
  `AND/OR` 先 fillna(0)、`IF` 的 NaN 取 a…两边**逐位同口径** ✓；
- 顺带加固：骨架若退化成**纯常量**（无预计算列、无入场价）⇒ 结果广播成"按标的的向量" ✓
  （否则引擎 `_sig[c]` 会炸 ✗ —— 单测抓到 ✓）。

**测试** ✓：`tests/test_exit_entry_rules.py` 重写（**35 passed** 合计含其他离场测试 ✓）——
