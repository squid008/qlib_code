# 数据源接入说明

本文档记录项目的数据源架构、E:\rq 数据目录结构，以及如何接入 rqalpha 数据源。

## 一、数据源架构

项目通过 `app/datasource/factory.py` 统一管理数据源，任何数据源都继承 `app/datasource/base.py` 的 `DataSource` 抽象基类，并实现统一的数据读取接口。

```
                 ┌─────────────────────────────┐
  前端/回测引擎  │   get_data_source(name)      │
                 └──────────────┬──────────────┘
                                │
                 ┌──────────────▼──────────────┐
                 │       DataSourceFactory     │
                 └───┬────────────┬───────────┘
                     │            │
          ┌──────────▼──┐   ┌─────▼──────────┐
          │ QlibDataSource │   │ RQAlphaDataSource │
          └──────────┬──┘   └─────┬──────────┘
                     │            │
               qlib cn_data      E:\rq bundle h5
```

### 数据源能力声明（capabilities）

| 能力 | qlib | rqalpha |
|------|------|---------|
| daily（日线） | ✅ | ✅ |
| minute（分钟） | ❌ | ✅ |
| financial（财报） | ❌ | ✅ |
| industry（行业） | ❌ | ❌（bundle 无独立行业文件） |
| index_constituent（指数成分） | ❌ | ✅ |

- **qlib**：只有日线行情，其余数据不包含。
- **rqalpha**：日线/分钟/财报/指数成分均可读，行业分类暂不可用。

> 注：前端回测界面已隐藏 rqalpha 选项。**回测引擎当前仅支持 qlib 数据源**（依赖 qlib 数据目录格式 DatasetH/D.features/D.calendar）。rqalpha 数据源已接入**数据查询 API**，供因子研究/数据浏览使用，但尚未桥接进回测引擎。

**实践建议（因子测试 / 回测起始日）**：

- 建议 **≥ 2013-01-04**：ST/涨跌停/市值/资金流字段全齐、股票 2500+ 只，口径与统计意义最好；

**「剔除 ST(T+1)」何时报错**（`backend/app/engine/limits.py::field_bin_available`）：

- 判定逻辑是"**扫描 features 下任一股票目录是否存在 `is_st.day.bin`**"（结果进程级缓存，**与所选日期无关**；换数据目录后需重启后端才会重新探测）；

### ★ 指数（`sh000xxx` / `sz399xxx`）**不物化**这些字段（2026-10-13 定 ✓）

**规则**：指数**只**有量价与派生量（`open/high/low/close/volume/amount/vwap/factor` ✓），
**一律不填** `is_st` / `limit_up` / `limit_down` / `chip_*` / `fin_*` ✗ ——
**Why**：这些字段的语义**只对个股存在** ✗（指数没有"ST 状态"、"涨跌停价"、"筹码分布"、"财报" ✗）
⇒ 硬填一个 0/NaN 出去就是**造假** ✗（会让"剔除 ST"「涨跌停过滤」「FINANCE()」对指数**静默给出错误结论** ✗）。
**How to apply**：① 补数据/体检时**不要**给指数补这些字段 ✗（`ai_test/fill_gaps_1009.py`、
`ai_test/fill_hdr_tail_1009.py` 都已显式排除指数 ✓）；② 看到指数目录里**已有**这类 bin ⇒ 视为历史遗留 ✗
（实测 `cn_data2` 的 6 只指数各有一个 header=2415（=2010-01-04）/**值全 0** 的 `is_st` bin ✗、
6 只都没有 `limit_up`/`limit_down` ✓，`chip_*` 4 只有值 2 只空 ✗ —— 都**不是**该有的东西 ✗）；
③ 回测/因子池里若要"只用个股"，用代码前缀过滤（`sh000*`/`sz399*` 即指数 ✓）。
④ ★ **2026-10-13 已删掉那 6 个假 `is_st` bin** ✓（用户同意 ✓；脚本 `ai_test/del_fake_index_is_st_1009.py`
——**先自证**：值必须全 0 才删 ✓，再备份到 `data/cn_data2/_backup_fake_is_st_20261013/` ✓）。
删掉**不会**影响「剔除 ST(T+1)」是否可用 ✓：`field_bin_available("is_st")` 扫的是
"**任一股票**目录是否存在该 bin" ✓（几千只股票都有 ✓）⇒ 不会因此报 400 ✓。

### 指数的量价口径（`cn_data2`，2026-10-13 实测反推 ✓）

本地指数价量是**乘恒定系数 f** 的口径 ✓（不是原始点位 ✗）：`price = index_daily × f` ✓、
`volume = index_daily.vol ÷ f` ✓、`amount` = 源（逐位相同 ✓）、`vwap = 10 × amount ÷ volume` ✓、
`factor ≈ f` ✓（实测 163 天漂移 ~1e-6 = float32 噪声级 ✓）。补齐脚本：`ai_test/fill_index_1009.py` ✓
（含**恒定系数闸门** ✓：漂移超 2e-4 就拒绝写 ✗）。
⚠ 指数 `turn`（换手率）**不要**拿 `index_dailybasic.turnover_rate` 直接续 ✗：实测两者**不是一个口径** ✗
（`sh000852` 重叠 118 天比值 0.0007~0.0015 且随日漂移 ✗）⇒ 要改就得**整条重建** ✓，不能"续尾" ✓。

> 探测脚本（本地，不入库）：`ai_test/probe_date_range.py`（日历范围 / 样例字段起点 / 各年覆盖数）、
> `ai_test/index_probe_1009.py`（指数逐字段覆盖 ✓）、`ai_test/cmp_index_daily_1009.py`（指数 bin vs tushare 对拍 ✓）。

### 各 h5 内部结构

**stocks.h5 / indexes.h5（日线）**
- key = 代码（`000001.XSHE` / `000001.XSHG`）
- 字段：`datetime(i8,YYYYMMDDHHMMSS)`、`open`、`close`、`high`、`low`、`prev_close`、`limit_up`、`limit_down`、`volume`、`total_turnover`

**bundle/h5/equities/{code}.h5（分钟线）**
- `data`：分钟结构化数组（`datetime/open/high/low/close/volume/total_turnover/num_trades`）
- `index`：`[date(YYYYMMDD), line_no]`，每日起始行号，用于切出每天 240 条分钟

**finance/pit/{code}.h5（财报）**
- `info_date`：公告日期（bytes `YYYY-MM-DD`）
- `quarter`：报告期（bytes `YYYYqN`）
- `fields`：Group，394 个财务字段，每字段一个 Dataset（如 `revenue`/`net_profit`/`total_assets`/`roe` 等）

**constituents/index/{code}.h5（指数成分）**
- `change_dates`：成分调整日列表
- `components`：Group，每个调整日一个子组存成分代码列表
- `weights`：三个并行数组 `date`/`order_book_id`/`weight`（含全量历史调整记录）

## 六、注意事项

- **不要全量读取**：E:\rq 总量约 150G。所有读取都是按需（指定代码/日期区间），按股票/指数/财报单文件访问。
